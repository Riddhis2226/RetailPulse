## Dataset Use in F04

- **Primary input:** sales transaction history, joined to customer records using a validated customer key.
- **Potential supporting inputs:** customer master attributes and the RFM features generated by F02.
- **Target definition:** the project plan proposes inactivity-based churn proxy rules (90-day inactivity and a 180-day dormant threshold); these assumptions need a clearly defined observation date and business validation.

The current Hugging Face verification script explicitly downloads `customer_master.csv`; the dataset inspection script lists all seven files. Do not interpret the proxy as observed customer churn, and do not use purchases after the prediction reference date as model features.


## Objective

Identify customers who may be at risk of becoming inactive so retail teams can prioritize retention outreach and investigate changes in customer engagement.

## Label Definition

The project notes propose inactivity-based churn rules, including **90 days without a purchase** and a **180-day dormant threshold**. These thresholds are business assumptions that must be documented and validated for the retail context.

An inactivity rule creates a **churn proxy label**; it is not proof that a customer has permanently churned. The label definition, observation date, and available history must be made explicit.

## Intended Workflow

1. Obtain validated transaction data and customer features from F01/F02.
2. Define the observation window and reference date.
3. Create churn-proxy labels using the approved inactivity rule.
4. Build customer features using information available at prediction time.
5. Split training and evaluation data without temporal leakage.
6. Train a baseline classification model.
7. Evaluate the model and choose a threshold appropriate to the business use case.
8. Produce customer-level risk scores and an interpretable summary.

## Evaluation

Evaluate more than accuracy, particularly when churn classes are imbalanced. Useful measures include:

- ROC-AUC and precision–recall metrics.
- Precision and recall at a chosen decision threshold.
- Precision among the highest-risk customers (for example, top 20%).
- Confusion matrix and calibration checks where appropriate.

The project brief specifies targets of **ROC-AUC ≥ 0.88** and **precision@top 20% ≥ 0.75**. These are acceptance targets, not achieved results; include them as results only if supported by a reproducible evaluation.

## Intended Outputs

- Customer identifier and churn-proxy label.
- Predicted churn risk or probability.
- Evaluation metrics and model metadata.
- A risk-ranked customer table suitable for retention analysis.

Do not expose unnecessary personal information in dashboard outputs. Use customer identifiers and aggregate insights where possible.
